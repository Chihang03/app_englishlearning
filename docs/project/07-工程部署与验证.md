# 工程、部署与验证

## 现行架构

浏览器 React/TypeScript 前端 → Nginx 静态页面与 `/api/` 反向代理 → Rust `english-server` → SQLite。Rust `englishctl` 承担维护、备份和内容操作，原生提醒任务由 systemd timer 调度。

Rust workspace 分为 core、storage、content、server 和 cli。生产发布包包含二进制、静态文件、部署配置、许可证及来源校验信息。Python 源码仍用于离线词库制作、审核、校准分析、参考实现和测试工具。

## 开发与验证

前端在 `frontend/` 执行 `npm run dev`，通过同源开发代理访问本地 API。生产构建使用 `npm run build`。后端构建和检查在 `rust/` 执行 `cargo build --workspace --locked`、`cargo test --workspace --locked`、`cargo fmt --all -- --check` 与 Clippy。

原生测验回归入口为 `backend/tests/test_assessment.py`，需要可用的本地原生 CLI 和 server。测试必须使用隔离数据库，绑定本地临时端口。浏览器回归通过 `frontend/tests/` 验证实际交互，按改动选择必要检查。

## 发布流程

1. 完成任务相关验证，按中文 Conventional Commits 提交并推送 main。
2. 在构建机生成 Linux 运行二进制与前端静态文件，保留 SOURCE_COMMIT 和 SHA256SUMS。
3. 上传到独立 release 目录并验证完整性。
4. 在服务器本地一致性副本中回放用例，核对原数据保留、请求结果、队列和资源表现。
5. 运行切换脚本，先备份，再安装必要扩展、切换服务和静态资源。
6. 检查公网版本、健康、实际二进制及服务状态，保存必要验收证据。

具体命令、运行环境变量、资源限制和恢复步骤以[原生发布手册](../../deploy/RUST.md)为准。服务目录为 `/opt/englishlearning/app`，数据目录为 `/var/lib/englishlearning/`，发布目录位于 `/opt/englishlearning/releases/`。

## 回退和数据保护

回退代码继续使用当前学习数据库，保留切换后的新作答。覆盖数据库属于单独的数据恢复操作，需先保存当前快照并核对差异。备份、密钥、真实账号数据和会话令牌不加入 Git 或发布包。

文档提交通过 Git 分发，运行时发布用于实际代码和资源变更。文档与代码更新后要核对入口链接、路由表、参数和验收边界。

## 验收分层

| 检查 | 能证明的范围 |
|---|---|
| 静态检查与构建 | 类型、语法及构建产物可生成 |
| 单元与隔离集成 | 指定输入和数据状态下的规则行为 |
| 服务器数据副本回放 | 真实数据结构上的兼容性及相关任务行为 |
| 手机尺寸浏览器 | 指定视口与模拟交互下的布局和流程 |
| 正式环境健康与版本 | 当前服务可访问且发布版本匹配 |
| 真实设备与真实延迟学习 | iOS 设备体验、实际完成时长和长期记忆效果 |

## 优先保持的回归

基础排除与水平模式独立保存，旧个人暂缓失效，标准复习不受水平暂缓干扰，长期熟记按原模型判定。测验保持 32–40 道纯理解题和每层至少四题，旧会话继续使用原版本。内容导入与发布保持历史、固定句和账号归属。
