# 账号、管理与数据架构

## 认证与身份

普通用户通过口令或 WebAuthn 通行密钥登录，服务器用 Cookie 会话识别账号。口令采用 scrypt 散列。通行密钥绑定站点 RP ID 和合法 Origin，服务器校验挑战、凭据归属和重放。用户可以管理自己的通行密钥、密码与时区。

学习账号与管理员按角色隔离。管理员登录后进入管理概览，可查看用户统计、反馈及处理状态，账号权限由服务端认证和路由共同执行。

## 管理流程

用户报告学习题目的问题，管理员查看题目快照、来源内容和说明，核对后修订内容并记录处理。批量审核采用导出、校验、导入过程。校验通过与实际导入分别记录，重复导入和部分失败需要保持一致。

## 数据关系与账号隔离

公共内容包括词头、来源义项、例句、词汇身份、课程及测验题库。账号数据包括会话、Passkey、所选词库、学习状态、历史、固定例句、曝光、个人记忆参数、水平档案、手动排除和提醒订阅。所有按账号读取与写入都应验证当前用户归属。

SQLite 主库继续使用 v22，测验与水平策略通过附加表扩展。HTTP 请求不负责迁移。显式维护命令先做包含 WAL 的一致性备份，再执行必要变更。

## 状态和事务

`study_attempts` 保存已签发题目，`review_history` 保存真实作答，`sense_srs_state` 保存学习进度，`adaptive_memory` 保存记忆模型状态。`assessment_sessions` 与 `assessment_responses` 保存测验流程。`user_unit_readiness` 与 `readiness_details` 保存历史及范围暂缓，`readiness_overrides` 保存主动恢复。

有效暂缓资格在账号请求内构造为 SQLite TEMP 集合。旧 personal_confirmation 记录保留审计来源，当前资格过滤只接受有效的范围确认，并排除已有标准复习状态的单元。

每个原生 API 用例持有事务，领域错误不能只提交部分修改。内容缓存使用连接内派生索引与版本检查。GET `/api/next` 具有签发题目的写入语义，需要按写请求处理。

## 离线与缓存

Service Worker 保存应用静态资源。学习内容快照和读缓存按账号区分，支持离线查阅及词形浏览。目录按内容分块校验与更新，分块下载同样验证学习账号；本地身份只用于只读浏览，不替代服务器会话。作答需要服务器确认，测验作答与个人 API 响应不进入公共静态缓存。细节见[缓存说明](../../deploy/CACHE.md)。

代码入口为 `api/accounts.rs`、`passkeys.rs`、`admin.rs`、`push.rs`，以及前端 `AuthScreen.tsx`、`PasskeySettings.tsx`、`AdminDashboard.tsx` 和缓存模块。
