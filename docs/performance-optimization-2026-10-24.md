# 性能与复杂度优化：2026-10-24

版本：26.10.24.99。生产后端已经是 Rust，本轮优化查询结构、重复计算、浏览器存储和传输，不引入新的运行语言或依赖。

## 实现

- SQLite 固定三个连接分别复用 TEMP 内容索引，保存规范化词头、基础词标志和学习单元可用性。内容版本与窄列指纹覆盖失效，课程归属、用户过滤和学习状态继续读取主库。基础词使用 CASE 短路计算，可用单元批量计算。HTTP 监听前完成索引预热，主库仍为 v22。
- 统计合并为复用 eligible/progress/due 集合的查询，减少重复的跨表筛选和到期集合计算。学习写入只改变用户状态，提交时记录连接自身的变化数，下一题无需再次扫描内容指纹；其他连接的变化继续校验。
- 词义与例句从逐义项查询改为两次批量查询。词形是否可学使用 EXISTS。曝光上传只读取必要 ID；反向词形先通过索引取小候选集合，再查询词义。词形分组保留原显示顺序，避免重复线性寻找已有分组。
- 浏览器 IndexedDB v3 分离小型元数据、轻量词头索引和逐词正文；启动与 304 不加载或重写完整正文。下载逐词解析，批次同时受 64 词与文本大小约束，完整成功后原子发布。保留旧版缓存直至迁移成功，并处理多窗口竞争与中断残留。
- 离线搜索找到 50 个结果即停止，不创建完整匹配数组；正文按 ID 读取。同学习单元的例句去重集合持续复用。
- 没有私有词条的账号在分别认证后共享服务器公共目录文件；有私有词条时保留账号隔离。构建时预压缩 JS/CSS，Nginx 提供预压缩资源，并为 JSON 等配置按需 gzip。

## 复杂度与空间

| 路径 | 优化前 | 优化后 |
|---|---|---|
| 同组多来源词义合并 | 累积例句集合反复重建，固定单来源大小时最坏平方级增长 | 每条新例句只规范化、检查一次，按总输入长度近似线性增长 |
| 目录热启动与 304 | 整体读取或存储完整目录，工作量随正文大小 B 增长 | 处理小型元数据；残留清理只遍历代次键，与正文 B 脱钩 |
| 目录下载处理 | response.json() 解析完整目录并常驻 | 单词解析与有上限批次；完整目录仍保存在磁盘，不常驻正文 |
| 单词正文 | 依赖整包正文的内存索引 | IndexedDB 按键读取该词正文；最近完整词义保留 50 项缓存 |
| 离线子串搜索 | 全扫描，先创建全部匹配数组，再截取 50 项 | 最坏仍为全扫描，额外结果空间最多 50 项，匹配足够时提前结束 |
| 例句查询 | 1 次词义查询加 S 次例句查询 | 两次查询，返回行处理仍随词义与例句总量增长 |
| 近期连续学习天数 | 先保留全部近期历史 JSON 行，再去重日期 | 流式读取，只保留去重日期，应用侧空间按天数增长 |
| 多个公共账号的目录文件 | 每账号保存完整公共正文 | 公共账号共享同内容版本文件；私有内容账号仍独立保存 |
| 完整统计 | 多组指标重复执行内容筛选、跨表查找和到期判定 | 静态索引复用，同次查询共用候选集合；完整统计仍含扫描、分组和去重 |

本轮没有将所有统计改成永久增量计数，也没有宣称统计已变成 O(1)。当前方式保留原统计口径、跨天与到期时刻语义，避免额外改变生产数据库结构。内容索引按固定连接复用，不随账号数复制一份完整候选集合。

## 同机隔离测量

时钟：`2026-10-24T06:55:06+00:00`。同一台约 914 MiB 内存的 Ubuntu 服务器，旧版 26.10.23.98 与新 Rust release 顺序运行。通过 SQLite backup API 从只读源建立一致性快照，再分别复制给两个版本；测试会话、曝光和答题只写入副本。数据为 13,424 个词、65,464 个词义、90,178 条例句、87,158 个学习单元和 157,592 条课程映射。

每个单接口热请求 10 次，以下为观测中位数。混合负载包含统计、课程、设置、日历和词典，每档 60 次。所有延迟为服务器环回 HTTP，不包含公网、TLS 或真实 iPhone 渲染。

| 接口 | 旧版中位数 | 新版中位数 | 耗时减少 |
|---|---:|---:|---:|
| 首页统计 | 871.76 ms | 146.15 ms | 83.2% |
| 课程进度 | 313.55 ms | 210.81 ms | 32.8% |
| 词典查询 | 9.36 ms | 8.02 ms | 14.3% |
| 更多词义：完整正文 | 6.34 ms | 2.61 ms | 58.9% |
| 更多词义：命中本地缓存 | 5.26 ms | 1.68 ms | 68.1% |

| 混合并发 | 总耗时：旧 / 新 | 观测 P95：旧 / 新 | 成功 / 总数：旧 / 新 |
|---:|---:|---:|---:|
| 1 | 14.21 / 4.72 秒 | 853.0 / 212.4 ms | 60/60 / 60/60 |
| 5 | 18.08 / 4.66 秒 | 3203.3 / 882.1 ms | 60/60 / 60/60 |

启动检查耗时为旧版 0.025 秒、新版 4.647 秒；新版包含三个连接的索引预热。启动后第一次统计请求为旧版 3006.5 ms、新版 361.2 ms。预热成本属于启动，不能解释为全应用启动提速。

取题单次检查为旧版 152.6 ms、新版 118.4 ms；答题后下一题为旧版 21.3 ms、新版 21.5 ms。这两项各一次，不作为稳定尾延迟分布。

最终进程峰值 RSS 为旧版 59.3 MiB、新版 51.2 MiB，包含前述全部接口、学习操作和目录构建。它不是浏览器内存，也不是 cgroup 总内存。本轮空间优化主要针对浏览器整包正文和多人重复目录，不声称所有请求的服务 RSS 都下降。

20 并发的无重试过载检查中，旧版状态为 `{'200': 12, '503': 48}`，新版为 `{'200': 16, '503': 44}`。固定 16 请求准入保护继续生效；503 请求未完成工作，不将快速拒绝当成吞吐提升。需要单独评估重试负载才能判断最终完成吞吐，本轮不调整准入上限。

## 传输与验证

| 构建资源 | 原始字节 | 预压缩字节 | 减少 |
|---|---:|---:|---:|
| JS | 313,125 | 96,445 | 69.2% |
| CSS | 36,940 | 8,223 | 77.7% |

压缩后解码字节与原资源逐字节一致，Service Worker 预缓存清单完整且不重复缓存 .gz 副本。线上是否实际返回 gzip 由发布后 HTTP 检查确认。

接口与学习动作响应对照通过，完整目录 35,190,486 字节与 SHA-256 完全一致，学习表记录数量一致，SQLite quick_check 与外键检查通过。聚合证据见 [最终 HTTP 对照](performance-evidence/2026-10-24/http.json)。原始数据库与会话仅留在服务器受限检查目录中。

验证还包括 Rust fmt、Clippy、9 项单元测试及 180 个 FSRS 固定场景，27 项接口与内容对照，以及最终学习路径的 4 项重点复核；前端 14 项单元测试、构建和真实 Chromium 的缓存迁移、离线重开、账号隔离、词义曝光、手动刷新与草稿保护回归通过。目录存储测试确认启动不读取正文、304 不写正文，并验证多窗口竞争、截断下载和中断残留清理。真实 iPhone 的内存峰值、启动时间和后台生命周期仍需设备实测。
