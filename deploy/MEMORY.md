# 小内存服务器运行与恢复

词义目录按单词逐条序列化为 `DATA_DIR` 下的磁盘快照，以数据库内容版本区分。Rust 服务在每次认证后，让没有私有词条的学习账号共享公共目录文件；有私有词条时仍按账号隔离。请求只在内容改变后生成新快照；匹配 ETag 时直接返回 304。修改词义、例句、归属或核心分组会由 SQLite 触发器使快照失效，答题和会话变化不触发重新生成。构建进程通过文件锁合并，并保留最近一天的旧版本供正在传输的响应使用。

数据库 v22 只新增目录版本元数据和失效触发器。升级前仍须使用 SQLite backup API 备份；原学习记录和账号不迁移、不清空。词义与译文补全的完整性核验忽略预期变化的版本计数，继续核对所有学习数据。

启动时逐块计算应用源码及词库文件指纹。上次同步成功、输入和相关数据库内容均未变化时复用结果；首次启动、输入改变或上次同步中断时重新同步。成功标记只在整个同步完成后保存。约 53 MiB 的词义核查包先逐条检查完整文档，再逐词应用，不同时解析整包。词库规范化哈希也逐块计算，保持原有内容指纹。

应用启动期间持有 `DATA_DIR/.startup.lock` 排他锁，提醒任务通过非阻塞共享锁跳过本次检查，下一分钟恢复。需要显式重做同步时，在服务停止、使用相同运行环境和服务账号的条件下调用：

```python
from app.database import init_database
init_database(force_sync=True)
```

约 1 GiB 内存的主机使用 `/swapfile-englishlearning` 提供 1 GiB 交换空间，权限 0600，写入 `/etc/fstab` 持久化，`/etc/sysctl.d/90-englishlearning-memory.conf` 设置 `vm.swappiness=10`。Swap 只缓冲峰值；仍应检查应用 RSS、内核 OOM 和磁盘等待。

部署使用独立版本目录并原子切换 `/opt/englishlearning/app`。保留原版本目录、独立虚拟环境和生产数据库。回退代码时切回原版本目录，v22 的新增元数据可保留，无需还原旧数据库覆盖新学习记录。线上备份及部署清单位于 `/var/backups/englishlearning-memory-*/`，目录仅 root 可访问。
